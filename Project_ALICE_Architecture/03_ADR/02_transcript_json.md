# ADR-002 transcript.json を会話の Source of Truth（源泉データ）とする決定

## ステータス
採用 (Accepted)

## 背景
音声文字起こしモジュール（`ALICE_Transcript`）の出力形式として、プレーンテキスト（`.txt`）のみを出力するか、タイムスタンプや話者情報を含む構造化データ（`.json`）を出力するかが議論された。

下流モジュールである `ALICE_Summary` や `ALICE_Minutes`、将来の分析モジュールが高度な処理（話者ごとの役割推定、発言の前後関係、原文照合監査）を行うためには、単なるテキストではなく時間と話者が厳格に紐付いた構造化データが不可欠であった。

## 決定
1. `ALICE_Transcript` は以下のスキーマを満たす `transcript/transcript.json` を会話の唯一の正本（Source of Truth）として必ず生成する。
2. 後続モジュールはこの正本 JSON を唯一の入力として読み込む。

### スキーマ定義
```json
[
  {
    "start": 0.0,
    "end": 2.45,
    "speaker": "SPEAKER_00",
    "text": "本日の定例会議を開始します。"
  }
]
```

| フィールド | 型 | 説明 |
| :--- | :--- | :--- |
| `start` | `float` | 発話開始時刻（秒） |
| `end` | `float` | 発話終了時刻（秒） |
| `speaker` | `string` | 話者識別子（例: `SPEAKER_00`, `UNKNOWN`） |
| `text` | `string` | 発話内容テキスト（正規化済み） |

## 影響
- **メリット**:
  - 会話のすべての発言について、秒単位のタイムスタンプと話者が永続化される。
  - 要約時の「Stage 3 原文照合（ハルシネーション検査）」が機械的に可能になる。
- **後方互換性**:
  - 人間可読用として、別途プレーンテキストの `transcript.txt` も同時に出力する。
