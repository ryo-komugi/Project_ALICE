## 1. ビジョンと基本理念

Project_ALICE は、日常生活や業務における音声・会話・日常対話から知識を抽出し、人々の意思決定と知的生産活動を強力に支援する**自律型・完全疎結合AIモジュール群**です。

中央のオーケストレーション基盤（`ALICE_Core`）と各専門機能モジュールが **Workspace Driven CLI 方式** で連携し、高い耐障害性、源泉データ主義、および再現性を備えたパーソナルAIアシスタント環境を提供します。

## 2. ALICE v1.0 ゴール定義 (Definition of Done)

ALICE v1.0 の正式達成基準（完了の定義）は、以下の要件をすべて満たし、安定運用できる状態を指します。

### 2.1 達成基準 (Success Criteria)

1. **自律的 E2E 処理パイプラインの安定稼働**:
   - 音声投入（LINE / Admin Web UI）から、文字起こし（`ALICE_Transcript`）→ 要約（`ALICE_Summary`）または議事録（`ALICE_Minutes`）の生成、および結果の LINE 配信までが人の介入なく完全自動で完結すること。
   - 異常発生時もジョブ単位でログが隔離保存され、中間成果物からの安全な再開（Robust Resume）が可能であること。
2. **源泉データ主義（Source of Truth）と 1 Job = 1 Workspace 原則の確立**:
   - すべてのジョブデータが `/data/runtime/workspaces/{job_id}/` に自己完結して保持されること。
   - 会話の正本 `transcript/transcript.json` を唯一の根拠として後続処理が行われ、ハルシネーションを排除する多段階パイプライン（3-Stage / 2-Stage）が機能していること。
3. **検索基盤と派生キャッシュ（Derived Cache）の分離**:
   - `ALICE_Search` による高速全文検索（SQLite + FTS5 trigram）・属性検索・1〜2文字LIKE自動補正が正常稼働すること。
   - ジョブ成否と検索インデックス更新の完全分離（成否境界）が保証され、インデックス更新エラーがジョブの成功を阻害しないこと。また、インデックス破損時も全 Workspace から 100% 再構築（`--reindex`）可能であること。
4. **オフロードメモリ基盤（ALICE_CoPilot）の連携**:
   - 日常対話からの短期・長期記憶の自動分類、および関係性（related / supersedes / conflicts）の管理が機能すること。
   - 起動時・更新時の Obsidian バウルト自動同期、および Discord からの `ALICE_Search` 過去成果物検索・引用がシームレスに行えること。
5. **運用管理性と可観測性の確保**:
   - Admin Web UI（PWA）により、ジョブのキュー状況・進捗・ワーカー状態が直感的にモニタリングできること。
   - CLI 契約（引数・終了コード・Primary Artifact）とロギング規約が全モジュールで遵守されていること。

### 2.2 v1.0 スコープ外（Non-Goals / KISS・YAGNI 原則の遵守）

憲章第1条（現実主義と実利用による進化）に基づき、以下の要素は v1.0 のスコープに含めず、将来マイルストーンで必要性が実証された場合にのみ検討します：
- **Vector DB / Embedding / 重厚な RAG 基盤**:
  - v1.0 では SQLite FTS5 trigram + BM25 による高速・軽量・堅牢な全文検索で十分な実用性を達成しており、GPU/VRAM リソース消費やモデル依存の大きい Embedding は採用しません。
- **複雑な Knowledge Graph DB**:
  - メモリのリレーションはファイルシステムと Obsidian のリンク構造で管理し、外部グラフ DB は導入しません。
- **分散マルチノードクラスタ構成**:
  - 単一マシン環境（ローカルサーバー）での Workspace Driven CLI による自立動作を最優先とします。

### Milestone 1 (M1): コア基盤と高精度音声認識パイプライン 【完了】
- **`ALICE_Core` の基盤構築**:
  - FastAPI による Webhook / API ゲートウェイ。
  - FIFO メモリキュー（`JobQueue`）とバックグラウンド実行ワーカ（`CoreWorker`）。
  - `1 Job = 1 Workspace` を管理する `WorkspaceManager` の実装。
  - LINE Bot 連携（音声受信および成果物プッシュ配信）。
- **`ALICE_Transcript` の確立**:
  - faster-whisper による高精度文字起こし。
  - Pyannote による話者分離（Diarization）。
  - ワードレベル話者アライメントと発話統合（Utterance Builder）。
  - 正本データ `transcript/transcript.json` スキーマの確立（ADR 002）。

### Milestone 2 (M2): 多段階LLM生成エンジン（要約・議事録） 【完了】
- **`ALICE_Summary` の 3 段階生成アーキテクチャ (Three-Stage Synthesis)**:
  - Stage 1: 会話構造化分析（`analysis.json`）。
  - Stage 2: 会話タイプ別テンプレートによるドラフト生成（`draft_summary.md`）。
  - Stage 3: 原文照合 7 項目監査と精密修正（`summary.md`, `summary.txt`, `consistency_report.md`）。
  - 長尺面談に対応する動的コンテキスト長スケーリング（32k〜64k）。
  - Ollama API タイムアウト・指数バックオフリトライおよびフェイルオーバー機構。
- **`ALICE_Minutes` の 2 段階議事録パイプライン (Two-Stage Pipeline)**:
  - Stage 1: 決定事項・アクションアイテム・議題経緯の厳格抽出。
  - Stage 2: 議事録の構造化整形（`minutes.md`, `minutes.txt`）。

### Milestone 3 (M3): ナレッジ検索基盤と派生キャッシュライフサイクル 【完了】
- **`ALICE_Search` の実装**:
  - SQLite + FTS5 trigram 転置インデックスによる高速全文検索。
  - 日本語の 1〜2 文字クエリに対する LIKE 自動補正とスニペット生成。
  - BM25 関連度スコアリングおよびユーザー・モジュール属性フィルタ。
- **成否境界（Safe Indexing Lifecycle）の実装**:
  - Job の成功完了（COMPLETED）と検索インデックス更新の完全分離。
  - 全 Workspace からの 100% インデックス完全再構築機能（`--reindex`）。
  - `ALICE_Core` Worker からの非ブロッキング更新連携。

### Milestone 4 (M4): 知識オフロード・メモリ同期・対話CoPilot 【完了】
- **`ALICE_CoPilot` の実装**:
  - 対話・ドキュメントからの短期記憶・長期記憶（Context / Projects / Decisions / Knowledge / Ideas）の自動分類。
  - メモリ間のリレーション管理（related / supersedes / conflicts）。
  - 起動時およびメモリ更新時の Obsidian バウルト自動同期。
  - Discord Bot インターフェース（対話、メモリ参照）。
  - Discord 上での `ALICE_Search` CLI 呼び出しによる過去音声成果物の検索・引用表示。

### Milestone 5 (M5): 運用管理Web UIとキューUX 【完了】
- **Admin Web UI (PWA) の実装**:
  - ジョブ一覧・詳細、キュー状態のリアルタイム可視化。
  - サイバーワンダーランド起動画面・BIZ UDP Gothic・プログレスバーによるUX向上。
  - LINE Flex メッセージによるリッチな完了通知と Web Viewer へのシームレスな導線。

### Milestone 6 (M6): v1.0 正式リリース・全系統結合テスト・運用ベースライン確立 【完了】
v1.0 を正式にリリースし、運用ベースラインを固定するための最終マイルストーン（2026-09-13 達成）。

## 4. マイルストーンの柔軟な運用と変更プロセス (Dynamic Milestone Governance)

Project_ALICE は実際の利用と日々の開発を通じて進化します。今後の開発過程において「これを入れたい」「あの機能も追加でほしい」といった新たな要求やアイデアが発生した場合、以下の合意形成プロセスを経てマイルストーンに随時組み込みます。

```text
[新機能・改善アイデアの発生]
          │
          ▼
┌──────────────────────────────────────────────┐
│ 1. 提案とディスカッション                   │
│    - 課題・ユーザー体験・実現したい価値の明確化│
└──────────────────────┬───────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────┐
│ 2. 憲章・アーキテクチャ原則への適合性チェック│
│    - モジュール疎結合 (Workspace CLI) の遵守 │
│    - 1 Job = 1 Workspace の維持              │
│    - 単一責任の原則 (責務の越境がないか)     │
└──────────────────────┬───────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────┐
│ 3. 影響度評価とマイルストーンプロット        │
│    - v1.0 の必須要件か？ (→ M6 へ組み込み)    │
│    - v1.0 後の拡張機能か？ (→ v1.x へプロット)│
└──────────────────────┬───────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────┐
│ 4. アーキテクチャ文書・ADR の更新            │
│    - 重要な設計変更は ADR を起草             │
│    - 本 Milestones ドキュメントの更新        │
└──────────────────────────────────────────────┘
```

### 4.1 変更ルールの原則
1. **随時相談と合意形成**:
   - 変更や機能追加は独断で進めず、まずユーザーと対話して「なぜ必要か」「どのモジュールの責務か」を合意します。
2. **スコープの適切な振り分け**:
   - v1.0 の安定稼働に直結するバグ修正や安定化は M6 に組み込みます。
   - 新規モジュールの新設や大規模な機能追加は、v1.0 のリリースを遅延させないよう v1.1 以降の次期マイルストーンへ割り振ります。
3. **ドキュメントの即時同期**:
   - マイルストーンの追加・順序変更が合意された場合、直ちに本ドキュメント（`Milestones_v1.0.md`）を更新して常に「生きたロードマップ」を維持します。

画面を見ずに、声だけでいつでも繋がれる究極のハンズフリー対話環境の構築。
- **自宅工房モード (Home Studio Voice / 案C)**:
  - 作業部屋やデスクに常駐するマイク ＆ スピーカーによる完全ハンズフリー対話。
  - ウェイクワード検知（「アリス」）＋ Whisper 高速認識 ＋ Ollama 推論 ＋ ローカル音声合成（TTS: VOICEVOX / Style-Bert-VITS2 等）によるリアルタイム口頭応答。
- **外出モバイルモード (Mobile PWA Voice / 案A)**:
  - スマホのホーム画面から PWA を開き、画面の波形を 1 タップして直接音声対話。
  - 外出先・移動先でもイヤホンを通じて声でやり取り。

#### Phase 4: v1.4 以降 - UX深化 & 高度自律連携 (Extended Intelligence)
- **専用モバイルクライアントアプリ (Flutter: Android/iOS) 【構想・ニーズ検証後】**:
  - **背景・方針**: まずは手軽な LINE 公式アカウントで仲間・知人に使ってもらい、実際の利用頻度や現場フィードバックを検証。ニーズの成熟に応じて専用モバイルアプリへ展開。
  - **コア価値**: 画面オフ・スリープでも絶対に途切れない長時間バックグラウンド録音（Foreground Service）、過去議事録・要約の手元オフライン/オンライン閲覧・全文検索（ALICE_Search連携）。
  - **LINE ログイン連携**: 既存の `line_user_id` と連携し、LINE Bot で作成した過去の議事録資産やユーザー名をそのままシームレスにアプリへ引き継ぎ。
  - **役割の明確な分離**: 一般ユーザーは手元のモバイルアプリ、管理者は厳重な MFA/パスレスで保護された WebUI コックピット（サーバー・GPU・ユーザー管理）へと役割を完全に二分。
- **Web UI ナレッジ検索画面**: Admin Web UI 上から過去の要約・議事録を直接検索・プレビュー。
- **話者名前マッピング・辞書機能**: `SPEAKER_00` を文脈やユーザー辞書から実際の人名へ自動置換。
- **直接テキスト/ドキュメント投入**: 音声なしでテキストメモや PDF/Markdown を直接要約・議事録化。
- **面談直前ブリーフィング**: カレンダー予定の開始15分前に、前回の要約と今回確認すべき論点を自動耳打ち。
- **ローカルLLMの推論効率化 & 通知チャネル拡充 (Slack/Webhook)**。
